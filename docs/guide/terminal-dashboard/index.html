The terminal dashboard

shard tui

Everything the web dashboard shows, drawn in the terminal you are already in. It is the right one to use over SSH, on a machine with no browser, or when you would rather not leave the keyboard.

Reading it

Nodes come from cluster.toml, and the bars from the last health check. Press h to run one now — it is the same check shard cluster health does, and the web dashboard shows the result too.

Runs are every run in the log directory, newest first. A run started in another terminal appears here within a second.

A run marked interrupted said it was running, but the process that started it is gone — a closed terminal, a laptop that slept. shard asks the operating system rather than believing the file.

The log at the bottom belongs to the highlighted machine and keeps up with the run as it goes. n and p move between machines, j and k scroll back through the output, G returns to the end, and Esc goes back to the list.

It only reads

Like the web dashboard, it cannot start work — it shows what is happening and what has happened. The one thing it changes is the health check, which is a read too.

If it will not start

shard: shard tui needs a terminal. For a browser, run: shard ui

That is what you get when the output is a pipe or a file rather than a terminal — in a cron job or a CI log, for instance. shard status and shard history are the plain-text versions.
