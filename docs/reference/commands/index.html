Commands

shard <command> [arguments] [options]

shard help prints a short version of this page. shard version prints the version.

Cluster

CommandWhat it does
shard cluster init Writes a cluster.toml in the current directory, containing this machine.
shard cluster add-node Asks for a machine's details and appends it to the file.
shard cluster list Shows the machines, their addresses, cores and tags.
shard cluster health Contacts every machine and reports which answered, with load and memory.
shard cluster remove <name> Removes one machine's block from the file, leaving your comments intact.

shard cluster health --on <where> checks part of the cluster.

Running work

shard exec "<command>" [--on <where>] [options]
shard exec-script <file> [--distribute] [--on <where>] [options]
shard map "<command with {i}>" --count <n> [--start <n>] [options]
shard pipeline --step "<command>" [--on <where>] [--name <label>] [--produces <path>] … [--parallel]
shard run <task-name> [options]

exec runs one command on each selected machine. exec-script sends a file to each machine's shell; with --distribute it shares the file's lines out between them instead. map runs one command many times with a changing number, spread across the machines. pipeline runs different commands in order, each on a machine of its own — --parallel starts them all at once instead. run does whichever of these a task in tasks.toml asks for.

OptionMeaning
--on <where> Machines to use: all, a name, a tag, or a comma separated list. Default all.
--jobs <n> How many machines may work at once. Default: all of them.
--timeout <seconds> Kill a machine's job after this long and report it as timed out.
--stream Print output as it arrives, each line prefixed with its machine.
--dry-run Print the command line for each machine and run nothing.
--no-log Do not write a log directory for this run.
--distribute exec-script only: split the file's lines between machines.
--count <n> map only: how many times to run the command. Required.
--start <n> map only: the first number given to {i}. Default 0.
--static map and --distribute: decide every machine's share before the run starts, instead of handing work out as machines finish.
--retry <n> Extra attempts for a failed job, or for a failed item in a map or distributed run.
--with <file> Ship this file or directory to each remote worker before it runs, and remove it after. May be repeated.
--keep Leave the shipped copy on the workers instead of cleaning it up.
--balance Measure each machine's live load first; size the work to the cores it has free, and drop machines that do not answer. For map and --distribute.
--step <command> pipeline only: one step. An --on, --name or --produces after it belongs to that step.
--produces <path> pipeline only: a file the step leaves behind, carried to the machines the later steps run on. May be repeated.
--parallel pipeline only: start every step at once instead of in order.
--tasks <file> run and tasks: use this file instead of searching for tasks.toml.

Named jobs

CommandWhat it does
shard tasks Lists the jobs in tasks.toml, with their strategy and steps.
shard run <name> Runs one of them. Options you type override what the file says.

shard run with no name lists the tasks, in case you forgot one.

The queue

shard queue add [--priority <n>] [--name "<label>"] -- <command>
shard queue list
shard queue run [--stop-on-fail]
shard queue remove <id>
shard queue clear
CommandWhat it does
queue add -- <command> Puts a job on the queue. Everything after -- is the command to run, exactly as you would type it after shard.
queue list Shows the waiting jobs, in the order they will run.
queue run Runs the jobs one at a time, highest priority first, until the queue is empty.
queue remove <id> Drops one waiting job. The id is shown by queue list.
queue clear Empties the queue.
OptionMeaning
--priority <n> queue add: higher runs sooner. Default 0. Ties break first-in, first-out.
--name <label> queue add: a label for the listing and the run.
--stop-on-fail queue run: stop the moment a job fails, leaving the rest queued.

Jobs live under ~/.shard/queue, one file each, so the queue survives the program exiting.

Looking at runs

CommandWhat it does
shard status Runs that are going on right now.
shard logs [<id>] Output of a run. With no id, or last, the most recent one.
shard logs <id> --node <name> Output from one machine only.
shard history [-n <count>] Past runs, newest first. Default 20.

The dashboards

shard ui [port]
shard tui

ui serves the dashboard on localhost, port 8787 unless you say otherwise — see The web dashboard. tui draws the same view in the terminal, and needs one: with its output redirected it says so and stops. See The terminal dashboard.

Global options

OptionMeaning
--config <file> Use this cluster file instead of searching for one.
--help, helpUsage summary.
versionVersion number.

The SHARD_CONFIG environment variable does the same as --config, for a whole shell session, and SHARD_TASKS does the same for --tasks:

export SHARD_CONFIG=~/work/build-farm.toml
export SHARD_TASKS=~/work/jobs.toml
