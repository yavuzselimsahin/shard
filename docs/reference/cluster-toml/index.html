cluster.toml

The file has one [cluster] block and one [[nodes]] block per machine. The double brackets matter: they are how TOML writes a list.

[cluster]

KeyDefaultMeaning
namethe machine's hostname What this cluster is called. Shown in listings and the dashboard.
log_dir~/.shard/logs Where run output is kept. ~ is expanded.

[[nodes]]

KeyDefaultMeaning
namethe host What you type to select this machine.
hostthe name Address or hostname. localhost runs without SSH.
useryour username SSH user.
keyyour default key SSH identity file. ~ is expanded.
port22SSH port.
tagsnone List of labels, for selecting groups: tags = ["cloud", "gpu"].
cpu1 Cores. Decides this machine's share when work is distributed.
ram_gbnone Memory, for your own reference. Shown in listings.
workdirthe login directory Directory to change into before running anything.
localfalse true runs commands here, without SSH. Implied by localhost.

A file using all of it

[cluster]
name    = "home-lab"
log_dir = "~/.shard/logs"

[[nodes]]
name    = "laptop"
host    = "localhost"
tags    = ["local", "fast"]
cpu     = 8
ram_gb  = 16

[[nodes]]
name    = "build-box"
host    = "192.168.1.15"
user    = "yavuz"
port    = 2222
workdir = "/srv/build"
tags    = ["cpu", "build"]
cpu     = 4
ram_gb  = 8

[[nodes]]
name   = "ec2-worker"
host   = "ec2-13-58-0-1.compute.amazonaws.com"
user   = "ubuntu"
key    = "~/.ssh/aws-key.pem"
tags   = ["cloud", "cpu"]
cpu    = 4
ram_gb = 8

What is understood

The reader covers the parts of TOML this file needs: comments, [table] and [[array of tables]] headers, strings, whole numbers, true/false, and lists of strings. Nested tables, dates and floating point numbers are not used, and a key it does not recognise is ignored rather than refused — so a note to yourself in the file does no harm.

A syntax error stops the command and names the line, rather than half-running on a misread cluster.
